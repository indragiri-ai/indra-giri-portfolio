# Indra Giri — Portfolio

Personal profile site for **Indra Giri** — AI Generalist, Senior Researcher, AI Trainer and Educator. Premium editorial design (deep navy + gold, dark default with a light toggle), Fraunces for display type, Inter for body, IBM Plex Mono for labels and figures.

## What's inside

- **Next.js 15** (App Router) + **TypeScript** + **React 19**
- **Tailwind CSS** with CSS-variable design tokens, dark + light themes (toggle in nav, persisted to `localStorage`)
- **Static export** (`output: "export"`) for GitHub Pages, with an `asset()` helper that handles the repo base path
- **Framer Motion** for reveal-on-scroll, the hero role flipper, and page transitions — all of it degrades under `prefers-reduced-motion`
- Nepal fieldwork map: all 77 districts as inline SVG, hover/tap/keyboard interactive
- Filterable research grid, career timeline, publications, teaching/training pages, blog
- Contact form via Formspree (falls back to a `mailto:` link if no Formspree ID is set)
- All content centralized in `src/lib/*.ts` — no CMS, no database

## Run it

```bash
npm install
npm run dev
```

Open <http://localhost:3000>.

Never run `npm run build` while `npm run dev` is active — it corrupts `.next` and the dev server starts 500ing. Stop the dev server first.

## Contact form (optional)

Copy `.env.example` to `.env.local` and add a [Formspree](https://formspree.io) form ID:

```env
NEXT_PUBLIC_FORMSPREE_ID=your_formspree_form_id
```

Without it, the contact form falls back to opening the visitor's email client with a pre-filled `mailto:` link.

## Edit content

Everything lives in `src/lib/`:

- `data.ts` — profile, roles, stats, about, AI practice, projects, publications, skills, teaching, journey, nav links
- `blog.ts` — blog posts as typed data
- `ai.ts`, `gallery.ts`, `fieldwork.ts` — standalone AI pages, gallery photos, and the Nepal map's district data

Edit the relevant file; the site updates. Never hand-edit `src/lib/nepal-map.ts` — it's generated by `scripts/build-nepal-map.mjs`.

Images: originals go in `source-images/` at the project root, never directly in `public/` (anything under `public/` ships to the live site verbatim). Process with sharp into `public/images/` before referencing them.

## Structure

```
src/
├── app/                 # / (one-page site), /blog, /ai, /projects, /training, /gallery
├── components/
│   ├── sections/        # Hero · About · AIPractice · Research · Skills · Teaching · Publications · Journey · BlogPreview · Contact
│   ├── layout/           # Navbar (mobile menu, theme toggle) · Footer
│   └── ui/               # SectionHead · Reveal · Counter · ThemeToggle · NepalMap · PageHeader
├── hooks/                # usePrefersReducedMotion
└── lib/                  # data.ts, blog.ts, ai.ts, gallery.ts, fieldwork.ts, nepal-map.ts (generated), utils.ts
```

## Deploy

A GitHub Pages workflow is already set up in `.github/workflows/`. Push to the deploy branch and it builds and publishes the static export automatically. Vercel also works out of the box (`next build` with `output: "export"`) if a custom domain is preferred later.
